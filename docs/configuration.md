# Configuration reference

This is the practical configuration index for Waycloak `v1.0.1`. It separates
settings owned by the verified installation transaction from Kubernetes
resources that operators and workload owners author after installation.

For the minimal application-facing path—one route plus one Pod-template label—
start with [GitOps workload onboarding](guides/gitops-workloads.md).

## Configuration ownership

| Area | Owner and source of truth | Change path |
| --- | --- | --- |
| Release version, manifest digest, chart digest, runtime image digests | signed `release-manifest.json` | `waycloakctl install plan/apply` |
| CNI paths, overlay CIDR, selected node architecture, observation trust | reviewed install plan | `waycloakctl install plan/apply` |
| VPN credentials | external credential source and namespaced Secret | Secret controller or `kubectl`; never Helm/KCL |
| Provider-native non-secret input | namespaced ConfigMap | operator/GitOps |
| Gateway intent | `VPNGateway` | operator/GitOps |
| Routing intent | `VPNEgressRoute` | workload or network owner through GitOps |
| Workload enrollment | Pod-template label | workload owner through GitOps |
| Inbound mapping | `PortForwardLease` and optional `WorkloadAdapter` | operator/GitOps |
| Runtime observations and bindings | controllers | read-only to users |

Do not copy values out of a plan and construct a hand-written installation.
The plan binds them to the observed cluster and to one immutable release.

## Installation settings

### Preflight

```sh
waycloakctl preflight \
  --context my-cluster \
  --overlay-cidr 100.96.0.0/16 \
  --output human
```

| Flag | Meaning |
| --- | --- |
| `--context` | kubeconfig context to observe |
| `--kubeconfig` | alternate kubeconfig path |
| `--overlay-cidr` | unused private IPv4 network, `/16` through `/29` |
| `--output` | `human` for operators or `json` for automation |

The overlay must not overlap Pod, Service, node, LAN, or VPN networks. It is a
cluster-wide data-plane identity and is not an application subnet.

### Install plan

```sh
waycloakctl install plan \
  --context my-cluster \
  --release-manifest release-manifest.json \
  --overlay-cidr 100.96.0.0/16 \
  --namespace waycloak-system \
  --node-architecture amd64 \
  --output json >install-plan.json
```

| Flag | Default/use |
| --- | --- |
| `--release-manifest` | required verified release inventory |
| `--namespace` | controller namespace; examples use `waycloak-system` |
| `--node-architecture` | restricts privileged DaemonSets to the selected architecture |
| `--enable-port-forwarding` | advertises and installs the qualified optional port-forward path |
| `--enable-adapter-protocol` | installs support for operator-selected application adapters |
| `--port-forward-controller-tls-secret` | pre-created immutable mTLS Secret required by the optional path |
| `--release` | Helm release name when an explicit non-default name is required |

Review the complete generated `valuesYAML` rather than maintaining an
independent values file for initial installation. Apply requires the exact
`.planID` as confirmation.

### Helm values

The chart schema is authoritative for render-time types. Most security-critical
values are generated by `waycloakctl` and include immutable image digests,
release identity, CNI receipt and host paths, node selection, and observation
trust. The operator-facing optional observability values are:

```yaml
observability:
  metrics:
    enabled: true
  assets:
    enabled: false
  openTelemetry:
    otlpEndpoint: ""
```

- Metrics are bounded aggregate signals and are enabled by default.
- Assets render optional Prometheus rules and a Grafana dashboard as
  ConfigMaps; they do not install those systems.
- An OTLP/HTTP endpoint enables bounded export to an existing receiver.
  Export failure never affects readiness.

See [Observability](operations/observability.md) and the
[Helm guide](guides/helm.md) before changing chart values.

## Gateway configuration

A `VPNGateway` selects the installed immutable `VPNGatewayClass`, references
credentials and native configuration, declares routing consent, and requests
optional capabilities.

The qualified `waycloakctl gateway init` baseline expects a Secret with exactly
the provider inputs `username` and `password` and renders this non-secret native
configuration (the overlay value must match the install plan):

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: private-gluetun
  namespace: media
data:
  VPN_SERVICE_PROVIDER: protonvpn
  VPN_TYPE: openvpn
  FIREWALL_OUTBOUND_SUBNETS: 100.96.0.0/16
  FIREWALL_INPUT_PORTS: "53,4789,18080"
```

Those firewall values are owned by the qualified recipe. Do not broaden them
to work around readiness or routing failures.

```yaml
apiVersion: networking.waycloak.io/v1beta1
kind: VPNGateway
metadata:
  name: private
  namespace: media
spec:
  gatewayClassName: gluetun.waycloak.io
  credentialRefs:
    - name: proton-credentials
      role: networking.waycloak.io/OpenVPNCredentials
  nativeConfigRefs:
    - name: private-gluetun
      role: networking.waycloak.io/GluetunEnvironment
  dns:
    mode: Gateway
  clusterTraffic:
    mode: TunnelAll
  allowedRoutes:
    namespaces:
      from: Same
```

### Gateway fields

| Field | Configuration |
| --- | --- |
| `gatewayClassName` | installed class; stable examples use `gluetun.waycloak.io` |
| `credentialRefs[]` | same-namespace Secret names and implementation-defined roles |
| `nativeConfigRefs[]` | same-namespace ConfigMap names and implementation-defined roles |
| `dns.mode` | `Gateway`; workload DNS stays on the protected gateway path |
| `clusterTraffic.mode` | `BypassCluster` or `TunnelAll` |
| `clusterTraffic.bypassCIDRs` | explicit additional cluster/private destinations to bypass when supported |
| `placement.nodeSelector` | select eligible gateway nodes |
| `placement.tolerations` | permit placement on intentionally tainted gateway nodes |
| `allowedRoutes.namespaces.from` | `Same`, `Selector`, or `All` |
| `allowedRoutes.namespaces.selector` | namespace selector used only with `Selector` |
| `requestedFeatures` | optional features the concrete gateway must provide |

Use `waycloakctl gateway init` for the qualified Proton/OpenVPN baseline. It
renders a non-secret ConfigMap and a matching gateway. Gluetun remains the
provider configuration boundary; Waycloak does not duplicate provider options
in its generic API.

### Credential access

The controller has no default permission to read arbitrary Secrets. Grant the
credential-reader role in each approved gateway namespace only:

```sh
kubectl -n media create rolebinding waycloak-gateway-secret-reader \
  --clusterrole=waycloak-gateway-secret-reader \
  --serviceaccount=waycloak-system:waycloak
```

Never use a `ClusterRoleBinding` for this role. Credential refs do not copy
Secret data into workloads, bindings, status, plans, or portable backups.

## Route configuration

A `VPNEgressRoute` connects workload intent to a gateway and can require
capabilities:

```yaml
apiVersion: networking.waycloak.io/v1beta1
kind: VPNEgressRoute
metadata:
  name: private
  namespace: media
spec:
  parentRefs:
    - group: networking.waycloak.io
      kind: VPNGateway
      namespace: media
      name: private
  requiredFeatures:
    - networking.waycloak.io/TCP
    - networking.waycloak.io/UDP
    - networking.waycloak.io/DNSContainment
```

Stable class capabilities include baseline fail-closed egress, TCP, UDP, DNS
containment, gateway replacement recovery, and node restart recovery. The
optional installation paths add `PortForwardServiceSingleActive` and
`WorkloadAdapter` support. A route remains unready if a requested capability is
not advertised and observed.

For a gateway in another namespace, the route names that namespace and the
gateway must authorize it through `allowedRoutes`. See
[Cross-namespace routing](advanced-setup.md#cross-namespace-routing).

## Workload enrollment

The only enrollment key is:

```yaml
networking.waycloak.io/egress-route: <same-namespace-route-name>
```

Put it on the workload's Pod template before Pod creation. Waycloak rejects
legacy annotations, malformed values, live-Pod enrollment changes, and
host-namespace or direct-node bypasses. Existing scheduling constraints are
preserved while admission adds the authenticated CNI-ready node requirement.

To delegate route and lease authorship in one namespace:

```sh
kubectl -n media create rolebinding waycloak-workload-owner \
  --clusterrole=waycloak-workload-owner \
  --user <user-or-group>
```

Use a namespaced `RoleBinding`, never a cluster-wide binding. Controllers own
`VPNWorkloadBinding`; users inspect it but do not create or edit it.

## Port forwarding and workload adapters

Provider port forwarding is opt-in at installation and at gateway/route level.
The application-facing contract is a stable Kubernetes Service and a
`PortForwardLease`:

```yaml
apiVersion: networking.waycloak.io/v1beta1
kind: PortForwardLease
metadata:
  name: peer-port
  namespace: media
spec:
  gatewayRef:
    name: private
    namespace: media
  backendRef:
    group: ""
    kind: Service
    name: peer-service
    port: 51413
  protocols: [TCP, UDP]
  endpointPolicy: SingleActive
```

Prefer a fixed application port with Waycloak translation. Add
`applicationAdapterRef.name` only when an application must be reconfigured to
advertise the provider-assigned port. An adapter is immutable operator trust,
has no Kubernetes token or VPN credential, and cannot weaken fail-closed
egress. qBittorrent is the reference last-resort adapter.

See [Workload adapters](guides/workload-adapters.md) for a complete
qBittorrent Service, adapter Deployment, immutable trust record, KCL example,
and adapter-bound lease. Third-party configuration ownership and official
upstream documentation are collected in [Dependencies](dependencies.md).

## Readiness and troubleshooting

Use conditions and `waycloakctl doctor` as the authoritative operational view:

```sh
waycloakctl doctor --context my-cluster --output human
waycloakctl doctor --context my-cluster --namespace media --route private
kubectl -n media describe vpngateway private
kubectl -n media describe vpnegressroute private
kubectl -n media get vpnworkloadbinding
```

`Ready=True` always describes current observed data-plane health. Do not work
around an unready resource by removing enrollment, bypassing preflight, editing
controller-owned status, or running raw Helm. Follow the ordered diagnostic
flow in [Advanced setup](advanced-setup.md#diagnostic-order).

For every field and condition, use the [generated API reference](api/v1beta1.md)
or `kubectl explain <resource>.spec --api-version=networking.waycloak.io/v1beta1`.
