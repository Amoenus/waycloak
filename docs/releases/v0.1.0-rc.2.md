# Waycloak v0.1.0-rc.2

`v0.1.0-rc.2` preserves the frozen `networking.waycloak.io/v1beta1` API and
stabilizes Waycloak's extension responsibilities. It remains a prerelease and
does not claim stable graduation.

## Changes from RC.1

- Gluetun is the VPN-engine and ordinary provider-support boundary.
- Proton NAT-PMP is a narrow Gluetun-selected port-forward capability rather
  than a Proton VPN adapter or a dependency of the generic runtime.
- incompatible Gluetun provider/tunnel configuration requesting port
  forwarding fails before gateway resources are mutated;
- fixed Service/backend ports use Waycloak-owned translation without an
  application adapter;
- `WorkloadAdapter` is explicitly a last-resort application compatibility
  contract;
- the installer flag is `--enable-adapter-protocol`, replacing the RC.1
  `--enable-qbittorrent-adapter` spelling;
- the install-plan field is `adapterProtocolEnabled`, replacing the RC.1
  `qBittorrentAdapterEnabled` field.

The CLI/plan renames are intentional prerelease clean breaks. No Kubernetes
kind, field, schema, feature identifier, or API version changes in RC.2.

## Upgrade

Download and verify the RC.2 `release-manifest.json`, then use that RC.2
`waycloakctl` binary to create and apply an exact release-transition plan. Do
not edit immutable release identity or use a raw Helm upgrade to activate the
new gateway template. Existing `VPNGateway`, `VPNEgressRoute`,
`VPNWorkloadBinding`, `PortForwardLease`, and `WorkloadAdapter` manifests remain
valid.

## Scope and limitations

- The supported quick path remains Gluetun with Proton OpenVPN.
- qBittorrent remains the reference application-adapter exception.
- Port-forward capability activation remains explicit and fail closed.
- Multi-gateway sharding/failover and Bitmagnet certification remain out of
  scope.
- Stable graduation still requires the tracked soak, lifecycle,
  exact-artifact, dependency, and final-v1 evidence.
