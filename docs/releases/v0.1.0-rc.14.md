# Waycloak v0.1.0-rc.14

RC.14 is the bounded gateway-health observation release candidate. It preserves
the frozen `networking.waycloak.io/v1beta1` API, RC.13's durable staged lease
handoff, and immediate fail-closed handling when the gateway agent actually
reports tunnel or DNS loss.

The first RC.13 local-cluster epoch exposed a separate observation-path defect.
The gateway agent and Gluetun DNS checks remained healthy, but an isolated
controller-to-agent HTTP observation failure temporarily changed the
`VPNGateway` to not ready. The lease correctly withdrew and recovered, but the
unchanged lease UID advanced from handoff generation 33 through 37. A raw
Kubernetes watch measured one representative gateway withdrawal from
09:19:50Z to 09:20:00Z and lease recovery at 09:20:02Z. The one-minute soak
collector missed the brief not-ready state, so that epoch is retained only as
lifecycle evidence.

RC.14 reuses one bounded HTTP transport and permits one independent retry only
for transient EOF, unexpected-EOF, connection-reset, or closed-idle-connection
observation failures. Timeouts, cancellation, HTTP error status, invalid
responses, and a valid response with `Ready=false` or `DNSReady=false` are not
retried. Genuine data-plane or DNS loss therefore still withdraws readiness
immediately; there is no permissive health hysteresis.

Controller logs now classify the observation phase and failure class and record
attempt count, latency, and recovery duration without logging the Pod address,
credentials, or the provider public endpoint. Successful bounded retries are
also visible as diagnostics.

RC.14 must be consumed by exact signed identity and deployed through GitOps. A
new minimum 72-hour unchanged-artifact epoch must run on the existing local
cluster with qBittorrent as the sole application canary. Bitmagnet remains at
zero replicas and no additional node is required.
