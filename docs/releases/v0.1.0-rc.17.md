# Waycloak v0.1.0-rc.17

RC.17 is the authoritative lease-reconciliation release candidate. It
preserves the frozen `networking.waycloak.io/v1beta1` API, completed DNS
observation semantics, strict stale-generation rejection, and immediate
fail-closed behavior.

The exact RC.16 deployment removed the false DNS signal: two consecutive
ten-minute local-cluster windows recorded zero Gateway Ready/DNSReady
transitions, no DNS or listener failures, fixed workload identities with zero
restarts, and 20 successful independent external TCP checks. The stable lease
UID nevertheless advanced from handoff generation 75 through 78, so neither
window started the graduation clock.

RC.17 begins each PortForwardLease reconciliation with the authoritative API
reader rather than a potentially lagging informer-cache resourceVersion. The
optimistic status precondition remains mandatory. A stale writer still
conflicts instead of regressing status, while ordinary reconciliation begins
from the current server object.

Every newly initiated drain also emits a sanitized transition reason that
distinguishes gateway unavailability, missing backend selection, Service UID
change, and Pod UID change. It records lease identity and current generation
but never a provider address or public port. This makes any remaining live
handoff actionable without weakening fail-closed withdrawal.

RC.16 remains useful exact-artifact, DNS-stability, qBittorrent listener, and
external-reachability evidence only. RC.17 must be consumed by exact signed
identity, deployed through homelab GitOps, and hold one generation through a
fresh stabilization window before a minimum 72-hour epoch starts on the
existing local cluster. qBittorrent remains the sole application canary;
Bitmagnet stays at zero and no additional node is required.
