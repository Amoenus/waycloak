# Waycloak v0.1.0-rc.16

RC.16 is the completed DNS-observation release candidate. It preserves the
frozen `networking.waycloak.io/v1beta1` API, RC.15's optimistic lease-status
concurrency, strict stale-generation rejection, and immediate fail-closed
behavior.

The exact RC.15 homelab deployment preserved the qBittorrent Pod and
PortForwardLease identities with zero restarts. A ten-minute pre-soak window
still caught a VPNGateway Ready/DNSReady withdrawal and recovery, handoff
generations 56, 57, and 59, and one provider mapping transition. Every healthy
sample retained both qBittorrent listeners, all ten independent external TCP
checks passed, and the gateway agent reported no completed probe failure.

The gateway agent had been clearing `DNSReady` at the start of every
one-second reconciliation, before its five end-to-end DNS probes completed. A
concurrent controller health observation could therefore consume a false
in-progress value even when all probes succeeded. RC.16 retains the last
completed successful DNS observation while a new probe is running. A completed
engine or split-DNS failure still clears readiness, reinstalls deny rules, and
returns the precise A/AAAA, UDP/TCP, validation/RCode, latency, and recovery
diagnostics. No failure threshold or permissive hysteresis is introduced.

The RC.15 pre-soak record is retained as fail-closed lifecycle and live
qBittorrent evidence, not graduation soak credit. RC.16 must be consumed by
exact signed identity and deployed through homelab GitOps. Only after it
settles without readiness or handoff churn may a fresh minimum 72-hour epoch
start on the existing local cluster with qBittorrent as the sole application
canary. Bitmagnet remains at zero replicas and no additional node is required.
