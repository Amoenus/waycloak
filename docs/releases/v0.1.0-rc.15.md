# Waycloak v0.1.0-rc.15

RC.15 is the monotonic lease-status release candidate. It preserves the frozen
`networking.waycloak.io/v1beta1` API, RC.14's bounded gateway-health
observation, strict stale-generation rejection, and immediate fail-closed
behavior.

The exact RC.14 GitOps upgrade preserved the qBittorrent Pod and
PortForwardLease identities but exposed a controller-handover race. A runtime
and persistent application adapter had accepted handoff generation 48 while an
older reconcile force-applied generation 47 without a Kubernetes
resource-version precondition. The runtime correctly rejected the regressed
request, and every forwarding readiness condition became
`Unknown/ObservationUnavailable`; Waycloak did not claim a working inbound
path.

RC.15 writes lease status with optimistic concurrency. A reconcile whose read
predates a newer status now receives a conflict and retries from current state
instead of overwriting the newer handoff generation. The focused regression
test advances stored status, attempts a stale lower-generation update, proves
the conflict, and proves the newer generation remains intact.

The RC.14 transition and generation-49 recovery are retained as fail-closed
lifecycle evidence, not soak credit. RC.15 must be consumed by exact signed
identity and deployed through GitOps. A new minimum 72-hour unchanged-artifact
epoch must run on the existing local cluster with qBittorrent as the sole
application canary. Bitmagnet remains at zero replicas and no additional node
is required.
