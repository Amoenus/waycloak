# Waycloak v0.1.0-rc.28

RC.28 is the publication successor to RC.27. It contains the same frozen API,
runtime implementation, dependency-backed stabilization, certified support row,
and fail-closed behavior described in the RC.27 notes.

The RC.27 runtime publication stopped at the vulnerability gate after Trivy
treated CoreDNS v1.14.7's exact release-commit pseudo-version as older than its
semantic release version. The official binary, image digest, release tag, and
source commit agree on v1.14.7. Nine reported CoreDNS findings were fixed by
v1.14.3 or earlier. Two x/mod findings affect module-download and transparency-
log verification code that is not reachable in Waycloak's fixed, read-only DNS
serving process.

RC.28 adds a reviewable, expiring Trivy exception for only those eleven findings
and only while scanning the exact selected CoreDNS v1.14.7 image digest. The
release scan displays the suppressed findings and continues to reject every
other fixed HIGH or CRITICAL vulnerability. The exception expires on 2026-11-27
and must be removed or re-qualified on dependency refresh. It is not a global
vulnerability waiver.

RC.28 is not deployable. Its runtime and CLI artifacts were published, but the
runtime workflow's independent redownload verification rejected the KCL OCI
manifest because the verifier expected an uncompressed tar artifact type while
the qualified KCL CLI published the canonical gzip tar artifact type. The tag
and published assets remain immutable. RC.29 supersedes RC.28 with the corrected
exact-media-type assertion.

Runtime and CLI publication, independent redownload verification, exact homelab
GitOps deployment, qBittorrent TCP/UDP listener, port-forward, DHT and torrent
checks, renewal and rotation evidence, and a new minimum 72-hour unchanged-
artifact local-cluster epoch remain mandatory before stable graduation.
