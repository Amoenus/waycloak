# Waycloak v0.1.0-rc.13

RC.13 is the staged handoff-generation release candidate. It preserves the
frozen `networking.waycloak.io/v1beta1` API, the workload-adapter protocol's
strict stale-identity rejection, RC.12's signed support matrix, and RC.11's
provider-ingress firewall composition.

The RC.12 GitOps activation exposed a two-phase ordering defect. During an
immutable WorkloadAdapter replacement, the controller's durable lease status
held generation 38 while the adapter had already applied generation 39 for the
same qBittorrent Pod. The adapter correctly rejected the stale withdrawal, and
gateway rules stayed withdrawn, but automatic recovery could not complete. The
old lease used its bounded cleanup quarantine before GitOps recreated it; the
qBittorrent Pod and its retained data were unchanged.

RC.13 persists a new endpoint and incremented generation in `Selecting` phase
before invoking provider acquisition, packet programming, neutral delivery, or
an application adapter. External effects occur only on the next reconcile. A
conflicting Kubernetes status write can therefore retry the same exact
generation rather than regress behind already-applied state.

The signed manifest retains one certified operator row: K3s
`v1.36.1+k3s1`, Flannel, containerd `2.2.3-k3s1`, Linux 5.10+, `amd64`, and
Gluetun configured for Proton/OpenVPN. Kind, k3d, `arm64`, and multi-platform
artifact availability remain test evidence rather than additional operator
support rows.

RC.13 must be consumed by exact signed identity and deployed through GitOps.
Its stable-graduation evidence begins with a fresh minimum 72-hour unchanged-
artifact local-cluster soak using qBittorrent as the sole application canary.
Bitmagnet remains scaled to zero and no additional node is required.
